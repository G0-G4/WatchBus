# Stop Arrival Prefetch Specification

## Purpose

Показывает ближайшие прибытия прямо в списке остановок и сокращает ожидание при открытии табло на Pebble.

## Requirements

### Requirement: Предварительная загрузка прогнозов

WatchBus SHALL показывать список сразу после поиска площадок и в фоне запрашивать прогнозы для первых пяти площадок или для всех, если их меньше пяти. При прокрутке WatchBus SHALL подгружать прогнозы для новых видимых площадок. Начальная загрузка SHALL сохранять порядок списка по расстоянию.

#### Scenario: Найдено больше пяти остановок

- **WHEN** поиск находит десять площадок
- **THEN** WatchBus сразу показывает список и ставит в очередь прогнозы для пяти ближайших. Для остальных запросы запускаются по мере появления площадок на экране

#### Scenario: Прогноз для видимой площадки уже загружается

- **WHEN** площадка повторно появляется на экране во время запроса
- **THEN** WatchBus использует текущий запрос

### Requirement: Краткое табло в списке

WatchBus SHALL показывать под площадкой до двух ближайших действующих прибытий в порядке времени с номером маршрута, временем ожидания и типом данных. Для выделенной площадки без действующего прогноза WatchBus SHALL после короткой паузы запросить расписание, если действующего расписания ещё нет.

#### Scenario: У выделенной площадки нет живых прогнозов

- **WHEN** запрос прогноза завершился успешно без действующих прогнозов и пользователь оставил площадку выделенной
- **THEN** WatchBus загружает расписание и показывает до двух плановых прибытий с пометкой «по расп.»

#### Scenario: Пользователь быстро пролистывает площадки

- **WHEN** выделение меняется до окончания паузы
- **THEN** WatchBus отменяет отложенный запрос расписания для предыдущей площадки

#### Scenario: Прогноз истёк

- **WHEN** срок действия прогнозной строки или время прибытия прошли
- **THEN** строка исчезает из списка

### Requirement: Приоритет открытого табло

WatchBus SHALL сразу открывать выбранную площадку по Select, показывать доступные действующие данные и загружать недостающие. Прогноз выбранной площадки SHALL иметь приоритет перед ожидающими фоновыми запросами. При открытии WatchBus SHALL переиспользовать выполняющиеся запросы той же площадки.

#### Scenario: Прогноз уже загружен

- **WHEN** пользователь открывает площадку с действующим предварительно загруженным прогнозом
- **THEN** табло показывает прогноз сразу, а расписание добавляется после загрузки

#### Scenario: Прогноз ещё загружается

- **WHEN** пользователь открывает площадку во время её фонового запроса
- **THEN** табло открывается и получает результат этого запроса

#### Scenario: Пользователь вернулся к списку

- **WHEN** пользователь нажимает Back до окончания запроса
- **THEN** WatchBus возвращает его к прежней позиции списка. Поздний ответ обновляет данные своей площадки, пока они актуальны

### Requirement: Актуальность и ошибки

WatchBus SHALL хранить данные каждой площадки отдельно, учитывать срок действия и соблюдать серверный `Retry-After` для фоновых и ручных запросов. Фоновый сбой SHALL оставлять список доступным. Минутное сетевое автообновление SHALL работать только на открытом табло.

#### Scenario: Изменилась геопозиция во время загрузки

- **WHEN** поиск по новой позиции заменяет список, а затем приходит ответ предыдущего запроса
- **THEN** ответ применяется только к площадке с соответствующим идентификатором
