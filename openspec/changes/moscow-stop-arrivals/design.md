## Context

WatchBus начинает с нового проекта. Документация PebbleKit JS описывает геолокацию телефона, HTTP-запросы и обмен с часами через AppMessage. Городской портал подтверждает наличие табло с прогнозами. Публичный контракт API для сторонних приложений пока не подтверждён. [PebbleKit JS](https://developer.rebble.io/guides/communication/using-pebblekit-js/) · [Портал «Московский транспорт»](https://transport.mos.ru/mostrans/all_news/125928)

## Goals / Non-Goals

**Goals**

- Получать прогнозы и расписание через телефон и передавать список площадок и компактное табло на часы.
- Проверить весь сценарий на Pebble Time 2 и Pixel 10 на Android. Зафиксировать версии и фактически проверенную совместимость.

**Non-Goals**

- Планирование поездок, избранное и фоновое отслеживание.
- Поддержка метро, МЦД, МЦК и речного транспорта в первой версии.

## Decisions

1. **Телефон получает данные, часы показывают табло.** PebbleKit JS обрабатывает геопозицию, поиск и HTTPS. Приложение на C показывает состояния и принимает команды кнопок. Общение начинается после события готовности JS. Для названий и маршрутов включаем шрифт с кириллицей и проверяем обрезку UTF-8 на часах.
2. **Первый кандидат — `stop_v2` «Московского транспорта».** Запрос без ключа к одной площадке вернул прогнозы с `byTelemetry: 1` для маршрутов 688 и 733 и записи с `byTelemetry: 0`. Проверяем смысл обоих типов записей, покрытие автобусов, электробусов и трамваев, соответствие ID площадок, лимиты, условия стороннего использования и прямой доступ с телефона. При необходимости проверяем другой бесплатный источник. Если подходящий бесплатный источник живых прогнозов не подтверждается, останавливаем реализацию и сообщаем пользователю. [Код стороннего клиента](https://github.com/zavorateam/moscow-transport-mcp/blob/main/clients/moscow_transport_client.py)
3. **Поиск ведётся по остановочным площадкам.** Адаптер возвращает московские площадки с ID, названием, типами транспорта и координатами. Телефон фильтрует их в радиусе 1 км и ранжирует по геодезическому расстоянию. При равном расстоянии первой идёт площадка с меньшим ID в лексикографическом порядке. При раздельных источниках соответствие ID площадки проверяется отдельно. Точные координаты хранятся в памяти на время поиска и передаются источнику только при необходимости поиска по координатам.
4. **Список и табло загружаются отдельно.** Телефон передаёт упорядоченные строки списка с ID, названием, расстоянием и доступным направлением или ориентиром порциями по мере прокрутки с учётом буферов AppMessage. Подсказка направления вычисляется при сборке каталога по последовательностям остановок из `route_v3`. Если у всех маршрутов, продолжающих движение с площадки, одна следующая остановка, показываем «Далее: …». Если следующие остановки различаются, показываем «В сторону: …» при общей конечной. При неоднозначных данных строка содержит название и расстояние. Select в списке передаёт ID выбранной площадки. Back с табло восстанавливает позицию в списке. Пункт «Обновить» в списке запрашивает позицию заново. Select на табло обновляет данные о прибытии по тому же ID.
5. **Часы получают снимок табло.** Телефон передаёт идентификатор запроса, состояние, название и ограниченный набор ближайших строк прогноза и расписания с типом данных. В каждой строке есть номер маршрута и абсолютное время прибытия. Телефон приводит плановые времена к абсолютному времени с учётом даты рейса и часового пояса источника. Размер набора определяется по буферам AppMessage выбранной платформы. Часы принимают полный снимок, игнорируют ответы от предыдущего запроса и пересчитывают ожидание на открытом экране. Прогнозы действуют до срока актуальности источника, максимум две минуты после получения. Плановые строки действуют до времени рейса в рамках срока действия расписания. Часы показывают действующие строки обоих типов по времени. Если источник позволяет надёжно сопоставить записи одного рейса, прогноз скрывает плановую строку на срок своей актуальности.
6. **Обновление работает на открытом табло.** Целевой интервал — одна минута. При открытом табло обновление работает без заданной квоты. Ручное и автоматическое обновления объединяются, если запрос уже выполняется. При HTTP 429 учитываем корректный `Retry-After`. При его отсутствии автообновление ждёт следующего обычного цикла. После Back автообновление прекращается. При сбое обновления часы показывают «Не удалось обновить» и сохраняют действующие строки. Тайм-аут обмена покрывает случай, когда JS не запустился или телефон отключился.

7. **Диагностика запросов.** Пишем в локальный лог PebbleKit JS тип запроса (ручной или автоматический), операцию, HTTP-статус, длительность и категорию ошибки. Для HTTP 429 фиксируем наличие `Retry-After` и время следующего запроса, если сервер его указал. Координаты, полный URL, тела ответов и учётные данные в лог не попадают. Лог доступен через инструменты отладки Pebble.

## Risks / Trade-offs

- Площадки через дорогу могут оказаться ближе по прямой → в списке видны обе площадки, а выбор проверяется на одноимённых площадках и точках рядом с перекрёстками.
- Контракт и доступность прогнозов могут меняться → держим преобразование ответов в адаптере и проверяем ответы с актуальным прогнозом, расписанием и ошибками.
- Эмулятор не подтверждает работу разрешений и сети на телефоне → перед сборкой первой версии проверяем геолокацию, HTTPS и AppMessage на целевой связке.

## Migration Plan

Новая установка из пакета `.pbw`. Проверка в эмуляторе с тестовыми данными и на целевой связке с реальным источником предшествует выпуску.

## Результаты проверки источника

13 ноября 2026 года четыре прямых запроса к `stop_v2` без ключа вернули табло. В каждом ответе UUID совпал с запрошенным. Ответы содержали координаты, название и внутренний ID площадки. На площадках «Клуб “Творческий городок”» и «Метро “Кунцевская”» были прогнозы по телеметрии для автобусов и электробуса 733. Ответы содержали `byTelemetry: 1` и `byTelemetry: 0`. Значение `0` показывает отсутствие телеметрии, его связь с опубликованным расписанием пока не подтверждена.

Дополнительная проверка подтвердила живой прогноз для трамвая 30 на площадке «Пехотная улица» (внутренний ID 460). UUID площадок получены из списка остановок маршрута в `route_v3` и приняты `stop_v2`. На проверенных площадках маршрута 17 в момент запроса были только записи с `byTelemetry: 0`.

В архиве GTFS от 30 июня 2026 года шесть проверенных площадок сопоставляются по `stop_id` из GTFS и `internal_id` из табло. Названия и координаты совпадают с учётом округления. Числовой ID не принимается напрямую в `stop_v2`. Для этих площадок UUID можно связать с каталогом через данные маршрутов и ответы табло. Получение актуального соответствия для всего города пока не проверено. Контрольный QR-код «Абрамцевской улицы» возвращает UUID и внутренний ID 2047. Подстановка проверенных `stop_id` или `global_id` из GTFS в QR-интерфейс вернула 404.

В пробных ответах отсутствовали заголовки с квотой. Опубликованная политика приложения описывает обработку персональных данных. Условия использования этого интерфейса сторонними приложениями и лимиты не найдены. Публичный городской GTFS предоставляет расписание. Бесплатная альтернатива с живыми прогнозами по Москве пока не подтверждена. [Политика приложения](https://api.mosgorpass.ru/v8.2/offers/mt_policy/html) · [Каталог GTFS](https://mobilitydatabase.org/feeds/gtfs/mdb-3226)

### Поиск ближайших остановок

- Локальный поиск проверен на архиве GTFS от 30 июня 2026 года. В файле остановок 17 896 строк с координатами до фильтрации по виду транспорта и городской принадлежности. В радиусе 1 км от «Клуба “Творческий городок”» получилось 34 записи, от «Пехотной улицы» — 55. Одноимённые площадки разделяются по ID. Например, четыре записи «Пехотная улица» оказались на расстоянии 0, 31, 79 и 107 м от контрольной точки. Локальный поиск не требует передачи геопозиции сервису. [Архив GTFS](https://mobilitydatabase.org/feeds/gtfs/mdb-3226)
- `route_v3` вернул площадки с UUID, названиями и координатами для трамваев 6 и 17 и электробуса 733. У шести проверенных площадок ближайшие записи в GTFS совпали по названию и лежали в пределах 0,27 м. Поле `num` обозначает позицию в маршруте, а `stop_v2.internal_id` совпадает с `GTFS stop_id` на проверенных площадках. Связь по имени и координатам пригодна для предварительного сопоставления. Совпадение следует подтверждать по внутреннему ID при запросе табло. [Код клиента маршрутов](https://github.com/ZhuravlevX/RailwaysTimetableTelegram)
- Прямой публичный поиск наземных площадок по координатам не подтверждён. Проверенные фильтры `suggest` для остановок отклонены или возвращают станции метро. Для локального варианта остаётся найти обновляемый каталог UUID с покрытием города либо подтвердить источник полного перечня маршрутов для подготовки такого каталога. Условия стороннего использования и лимиты запросов к живым табло остаются неизвестными.

Сквозная проверка привязки прошла для 8 площадок, включая обе площадки «Клуб “Творческий городок”» и четыре одноимённые площадки «Пехотная улица». Цепочка использует `stop_times → trips → routes` в GTFS, точное совпадение номера и вида транспорта в `suggest`, координаты площадки из `route_v3` и проверку `stop_v2.internal_id == GTFS stop_id`. Все 8 табло подтвердили ID. Отдельная выборка из 12 номеров нашла точное совпадение для каждого. Для номера 17 сервис вернул автобус и трамвай, для «Б» — два автобусных маршрута. При совпадении номера и вида транспорта нужно рассматривать все найденные варианты и проверять площадку.

Архив содержит 841 автобусный и 35 трамвайных маршрутов, а также один маршрут другого типа. Для общегородской привязки предлагается заранее собирать компактный каталог площадок с UUID и проверять его покрытие по GTFS. Полный обход городских маршрутов пока не выполнялся. Неизвестны допустимая частота запросов и условия стороннего использования.

Расширенная сверка охватила 14 номеров автобусных и трамвайных маршрутов. Городской сервис вернул маршрутные карточки для всех 14. У двух маршрутов («м59» и «с554») в архивном GTFS не оказалось связанных площадок через `stop_times → trips → routes`, поэтому в расчёте покрытия участвовали 12 маршрутов. Для 620 из 733 уникальных площадок GTFS нашёлся ровно один UUID в пределах 3 м на соответствующих маршрутах, для 113 совпадений в пределах порога не было. Это предварительная географическая привязка. Сверка внутреннего ID табло остаётся обязательной для подтверждения конкретного соответствия. У трамвая 11 нашлось 37 из 82 площадок, у ночного автобуса «н3» — 71 из 98. Эти результаты показывают, что архив GTFS годится для проверки покрытия и дополнения расписанием, а список площадок с живым табло целесообразно строить непосредственно из актуальных карточек `route_v3`, где уже есть UUID и координаты. Для общегородского каталога остаётся подтвердить полный перечень маршрутов и порядок допустимого обновления.

### Актуальный перечень маршрутов

13 ноября 2026 года последовательно проверены все 20 страниц официального расписания. Они вернули 978 карточек с разными ID портала и 972 уникальные пары «номер, значок вида транспорта». Из карточек 34 помечены значком трамвая, одна — троллейбуса, у 943 такого значка нет. В перечне есть «м59» и «с554», у которых предыдущая сверка с архивом GTFS не нашла связей с остановками. Первая страница доступна напрямую, остальные загружает публичный интерфейс прокрутки через `getRoutesList`. Параметр `page` на основном URL выдаёт первую страницу повторно. [Городское расписание](https://transport.mos.ru/transport/schedule)

Этот перечень подходит как источник номеров и направлений для сборки каталога. ID карточки портала и UUID маршрута `route_v3` относятся к разным интерфейсам. Для привязки используем проверенную цепочку через `suggest` и сверяем направление при повторяющихся номерах. Полный проход от 978 карточек до UUID площадок пока не выполнен. В публичных материалах найдены пользовательские табло и канал обратной связи, а опубликованных квот и условий стороннего доступа к `stop_v2` не найдено. [Способы обращения в «Московский транспорт»](https://transport.mos.ru/mostrans/feedback/service_center)

### Площадки и плановые времена в карточках расписания

Три проверенные карточки портала содержат карту GeoJSON с числовыми ID площадок, названиями и координатами. Карточка трамвая «А» для направления 0 и даты 13 ноября 2026 года содержит 24 площадки и плановые часы и минуты по остановкам. Все 24 точки карты однозначно сопоставились с площадками `route_v3` в пределах 3 м. У пяти проверенных табло числовой ID из GeoJSON совпал с `stop_v2.internal_id`. UUID табло в карточках портала не найден. Поле `data-stop` в разметке расписания содержит порядковый номер, а числовой ID площадки берётся из GeoJSON. [Карточка трамвая «А»](https://transport.mos.ru/transport/schedule/route/1048)

Это даёт актуальный источник числовых ID и плановых времён для сверки с живым каталогом. Перед использованием расписания в приложении остаётся проверить обратное направление, смену даты и переход через полночь. Массовая сборка общегородского каталога и условия регулярного стороннего доступа к живым табло пока не подтверждены.

Проверено переключение направления и даты через публичную форму расписания. Для трамвая «А» на 13 ноября 2026 года прямое направление вернуло 24 площадки, обратное — 23 с другими начальными ID. Запрос обратного направления на 14 ноября вернул ту же последовательность площадок и другое расписание с новой датой. Для ночного маршрута «н3» (актуальная карточка 1337) на обе даты вернулось по 48 площадок. На первой площадке строки часов идут в порядке `00, 01, 02, 03, 04, 23`. Например, указаны 00:24, 00:54 и 23:54. Ответы явно помечены запрошенной датой. Для планового табло возле полуночи нужно учитывать расписания обеих соседних календарных дат в московском часовом поясе и сортировать абсолютные времена, без переноса ранних строк на следующий день по порядку в разметке. В проверенном ночном примере времена обеих дат совпали, поэтому он не подтверждает привязку рейса, начавшегося до полуночи, к конкретной дате отправления. [Расписание трамвая «А»](https://transport.mos.ru/transport/schedule/route/1048) · [Расписание «н3»](https://transport.mos.ru/transport/schedule/route/1337)

### Как отличать прогноз от расписания

На четырёх проверенных площадках `externalForecastTime` был пуст во всех просмотренных строках маршрутов. Записи `externalForecast` содержали относительное время, `byTelemetry`, `tmId` и `routePathId`. Общего идентификатора рейса с плановым расписанием в просмотренных ответах нет. На трёх последовательных площадках трамвая «А» записи с `byTelemetry: 0` отличались от опубликованных плановых минут и пропускали несколько плановых рейсов. Например, для Октябрьского трамвайного депо по времени HTTP-ответа они соответствовали примерно 16:22, 17:03 и 17:07, а в карточке были 16:20, 16:29, 16:38 и другие времена. Значение `0` недостаточно для метки «по расп.». Для неё используем явные плановые времена из расписания. Совпадения по номеру и близкому времени не считаем подтверждением общего рейса. [Карточка трамвая «А»](https://transport.mos.ru/transport/schedule/route/1048)

### Покрытие трамвайных маршрутов

Проверены все 34 трамвайные карточки из городского списка. Для каждой найдена карточка `route_v3`. Собрано 853 уникальных UUID площадок с координатами, включая площадки вариантов маршрутов. У 29 карточек совпали номер, вид транспорта и названия конечных. Для пяти карточек (10, 11, 30, 38 и 50) нашлось по одному кандидату того же номера и вида, а названия одной из конечных различались. Сверка карт расписания в направлении по умолчанию дала однозначный UUID в пределах 3 м для всех 157 точек этих пяти маршрутов. Это подтверждает соответствие маршрутов на проверенном направлении. Число 853 отражает объём каталога из ответов `route_v3`. Оно не измеряет долю площадок с действующим прогнозом. [Городское расписание](https://transport.mos.ru/transport/schedule)

### Покрытие автобусных маршрутов

Взято по одной нетрамвайной и нетроллейбусной карточке из середины каждой из 20 страниц городского расписания. Для всех 20 нашёлся единственный точный кандидат по номеру и виду транспорта. У 16 совпали конечные, у четырёх различие конечных удалось проверить по картам. Все 510 точек направления по умолчанию однозначно совпали с точками `route_v3` в пределах 3 м. Карточки `route_v3` дали 882 уникальных UUID с учётом обоих направлений и вариантов маршрутов. Это выборка, а не оценка общегородской доли покрытия.

В этой выборке все 20 карточек `route_v3` имели `electrobus: false`. Отдельная проверка маршрутов 733 и «н3» вернула `type: bus` и `electrobus: true`, а «е10» и «е12» — `type: bus` и `electrobus: false`. Буквенный префикс номера не используется для определения электробуса. Признак `electrobus` интерпретируется вместе с `type`, поскольку на проверенной карточке трамвая 17 он тоже был истинным. [Городское расписание](https://transport.mos.ru/transport/schedule)

### Проверка обновления табло

Два запроса к табло «Клуб “Творческий городок”» без ключа с интервалом в 60 секунд вернули HTTP 200. Для одной и той же машины маршрута 733 ожидание изменилось с 403 до 346 секунд. Заголовки квоты, срока кэша и `Retry-After` в этих ответах отсутствовали. Проверка подтверждает, что с минутным интервалом можно получить обновлённое табло на одной площадке. Допустимую частоту регулярного использования она не устанавливает. Опубликованный адрес поддержки приложения — `welcome@mosgorpass.moscow`. Через него можно уточнить бесплатный доступ к прогнозам, допустимую частоту запросов и разрешённый способ обновления каталога площадок. [Контакты разработчика приложения](https://play.google.com/store/apps/details?id=ru.mosgorpass)

Решение для MVP: используем подтверждённый доступ к `stop_v2` без ключа. Неизвестные квоты и условия стороннего использования зафиксированы. Минутный интервал применяется без заранее заданной квоты, с учётом ответа сервера. Сопоставление остановок подтверждено на выборке, полное покрытие города ещё предстоит измерить.

### Проверка сборки на устройствах

Пользователь подтвердил, что WatchBus 1.1.0 работает на Pebble Time 2 с Pixel 10 на Android после установки пакета `WatchBus.pbw`. Пользователь подтвердил, что проверки на месте прошли, включая открытие двух соседних табло, ручное обновление и восстановление после отключения Bluetooth, геолокации и интернета. Сверка ID и прогнозов с источником, сетевое автообновление по журналу и пересортировка списка после смены позиции пока не подтверждены.

На эмуляторе Emery первый сетевой запрос табло прошёл в 17:05:56, автоматический — в 17:06:55. После Back и ожидания более минуты новых запросов не было. Пункт «Обновить» после смены координат перестроил список с «Клуба “Творческий городок”» на «Пехотную улицу». Исправлен разбор расписания, когда номера строк сдвинуты относительно GeoJSON. После исправления табло на проверенной площадке одновременно показало живой прогноз 733 и плановые рейсы 688 и 733.
