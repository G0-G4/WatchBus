## Purpose

Позволяет пассажиру посмотреть на Pebble, через сколько прибудет наземный транспорт на выбранную из ближайших остановок в Москве.

## ADDED Requirements

### Requirement: Список ближайших остановок

WatchBus SHALL при открытии получить актуальную геопозицию сопряжённого телефона и показать прокручиваемый список остановочных площадок московского наземного транспорта в пределах 1 км по возрастанию расстояния по прямой. Каждая строка SHALL содержать название, расстояние и направление или ориентир, когда источник их предоставляет. Площадки с одинаковым названием SHALL отображаться отдельно по их идентификаторам.

#### Scenario: Две площадки по разные стороны улицы

- **WHEN** в пределах поиска есть две одноимённые площадки и одна ближе к телефону
- **THEN** WatchBus показывает обе площадки отдельными строками, начиная с ближайшей, и добавляет доступные направления или ориентиры

#### Scenario: Рядом нет остановок

- **WHEN** поиск успешно завершён и в радиусе 1 км нет подходящих площадок
- **THEN** часы показывают «Рядом нет остановок»

### Requirement: Табло прибытия

WatchBus SHALL показывать название выбранной площадки и прокручиваемый список ближайших прибытий автобусов, электробусов и трамваев по времени. Каждая строка SHALL содержать номер маршрута, время ожидания и пометку «прогноз» или «по расп.». Прогнозы и плановые рейсы SHALL отображаться вместе. Если надёжный идентификатор или иной признак подтверждает совпадение рейса, действующий прогноз SHALL заменять плановую строку. При неопределённом совпадении обе строки SHALL оставаться в списке.

#### Scenario: Пользователь выбирает площадку из списка

- **WHEN** пользователь нажимает Select на строке площадки
- **THEN** WatchBus запрашивает данные о прибытии по её идентификатору и открывает её табло

#### Scenario: Возврат к списку

- **WHEN** пользователь нажимает Back на табло
- **THEN** WatchBus возвращает его к списку площадок с сохранением позиции в списке

#### Scenario: Несколько прибытий

- **WHEN** источник возвращает актуальные прогнозы с ожиданием 40 секунд, 3 и 7 минут
- **THEN** часы показывают их по возрастанию времени с пометкой «прогноз», обозначая первое прибытие как «< 1 мин»

#### Scenario: Доступен частичный прогноз

- **WHEN** у автобуса 42 есть прогноз на 3 минуты, а у трамвая 7 только расписание на 5 минут
- **THEN** часы показывают «42 · 3 мин · прогноз», затем «7 · 5 мин · по расп.»

#### Scenario: Прогноз и расписание одного рейса

- **WHEN** прогноз и расписание надёжно сопоставлены с одним рейсом
- **THEN** часы показывают этот рейс один раз с прогнозным временем

#### Scenario: Совпадение рейсов не подтверждено

- **WHEN** у двух записей совпадает номер маршрута и близко время прибытия, а надёжного признака совпадения рейса нет
- **THEN** часы показывают обе записи с их пометками

#### Scenario: Источник вернул только расписание

- **WHEN** источник успешно ответил и для остановки доступны только плановые времена
- **THEN** часы показывают название остановки и ближайшие плановые рейсы по времени с пометкой «по расп.»

#### Scenario: Поступивший прогноз истёк

- **WHEN** время прогнозируемого прибытия уже прошло или полученное табло утратило актуальность
- **THEN** часы убирают истёкшие значения. Доступные будущие плановые рейсы отображаются с пометкой «по расп.»

#### Scenario: Нет данных о ближайших прибытиях

- **WHEN** для площадки нет действующих прогнозов и доступных будущих рейсов по расписанию
- **THEN** часы показывают «Нет данных о прибытии»

### Requirement: Обновление и ошибки

WatchBus SHALL обновлять список по пункту «Обновить» и повторно запрашивать данные о прибытии для выбранной площадки по Select на её табло. Пока табло открыто, WatchBus SHALL автоматически обновлять его с целевым интервалом в одну минуту. При HTTP 429 с корректным заголовком `Retry-After` приложение SHALL отложить оба вида обновления до указанного времени. При первой загрузке часы SHALL показывать загрузку. При ошибке обновления часы SHALL показывать «Не удалось обновить» и сохранять действующие данные. Select SHALL позволять повторить запрос после указанной сервером паузы, если она действует.

#### Scenario: Пользователь обновляет список после перемещения

- **WHEN** пользователь выбирает «Обновить» после смены позиции
- **THEN** WatchBus повторно получает геопозицию и показывает список по возрастанию расстояния от новой позиции

#### Scenario: Пользователь обновляет табло

- **WHEN** пользователь нажимает Select на табло площадки
- **THEN** WatchBus запрашивает свежие данные о прибытии для той же площадки

#### Scenario: Источник временно ограничил запросы

- **WHEN** источник возвращает HTTP 429 с `Retry-After`, который требует ждать дольше минуты
- **THEN** WatchBus выдерживает указанную паузу и для автообновления, и для Select. После выхода с табло автообновление прекращается

#### Scenario: Обновление табло не удалось

- **WHEN** запрос обновления завершился ошибкой при открытом табло
- **THEN** часы показывают «Не удалось обновить», сохраняют действующие прогнозы и плановые рейсы и убирают строки по мере истечения их срока

#### Scenario: Геолокация отключена

- **WHEN** телефон отклонил доступ к геолокации или позицию не удалось получить
- **THEN** часы показывают подсказку проверить геолокацию телефона

#### Scenario: Телефон отключён

- **WHEN** часы не могут обменяться данными с телефоном
- **THEN** часы предлагают проверить подключение к телефону

#### Scenario: Источник недоступен

- **WHEN** первоначальный запрос остановок или табло завершился ошибкой, тайм-аутом либо ответом непригодного формата
- **THEN** часы сообщают, что транспортные данные недоступны, и предлагают повторить запрос
