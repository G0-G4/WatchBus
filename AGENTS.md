# WatchBus

- **Поведение.** При изменении пользовательских сценариев сверяйся с требованиями в `openspec/specs/` и соответствующим активным изменением из `openspec list`. Незавершённые требования базового приложения находятся в `openspec/changes/moscow-stop-arrivals/`.
- **Табло.** `src/pkjs/transport.js` получает и нормализует данные. Помечай живым прогнозом только записи с `byTelemetry: 1`. Плановые времена бери из расписания. Объединяй строки одного рейса только при надёжном совпадении идентификаторов.
- **AppMessage.** При изменении протокола сверяй `package.json`, `src/pkjs/index.js` и `src/c/watchbus.c`. Проверяй размер сообщений с кириллицей и отклонение ответов от предыдущего поиска или табло.
- **Каталог.** При изменении схемы или данных используй генератор `scripts/build_catalog.py` и команды из [README](README.md#данные-и-каталог-остановок). Проверь, что читатели каталога понимают новый формат.
- **Проверки.** Для логики запускай `node --test tests/*.test.js`. Для изменений приложения выполняй `pebble build`. Для интерфейса и AppMessage проверяй соответствующий сценарий в эмуляторе `emery`. Результаты на эмуляторе и физических устройствах фиксируй отдельно.
